How our website works

Our website is made of four free online services that work together. This guide shows what each one does, and what happens behind the scenes when you sign in, when a visitor sends a message, and when you update a page.

The four parts of our website, and how they talk to each other.

The four parts

All four are free for a website our size. Each has its own account, owned by Elim Bath.

GitHub

The filing cabinet

Stores everything the website is made of: the words on every page, the pictures, the menu and the design. Every change is kept as a dated version, with the name of the person who made it.

Like a filing cabinet that never throws anything away.

Cloudflare

Where the website lives

Shows the website to anyone who visits. When something changes in GitHub, Cloudflare rebuilds the site and puts the new version live. It also runs two small helpers: one for signing in, one for the contact forms.

Like the shop window, and the person who rearranges it.

OAuth App (on GitHub)

The sign-in desk

A small setting inside GitHub that lets our website ask GitHub, “who is this person, and may they edit?” It means editors sign in with their GitHub account; the website never sees or stores anyone’s password.

Like a front desk that checks ID and hands out a visitor’s pass.

Resend

The postman

Turns the messages visitors type into the website’s forms (the contact form and venue hire enquiries) into emails, and delivers them to the church inbox.

Like a postman who only carries letters from our website.

1When you sign in as an editor

Editing happens at www.elimbath.org/admin.

You→ Cloudflare→ OAuth App→ GitHub→ Back to you, signed in
  1. You open www.elimbath.org/admin and click “Login with GitHub”. A small sign-in window opens. Cloudflare’s sign-in helper sends that window to GitHub.
  2. GitHub asks you to sign in (if you aren’t already) with your own GitHub username and password. The first time, it also shows our OAuth App and asks you to approve it: this is GitHub asking “do you allow the Bath Elim website to make changes for you?”
  3. GitHub hands back a pass. Once you approve, GitHub gives Cloudflare’s helper a temporary pass for you. The helper uses a secret key, kept safely in Cloudflare, to prove it really is our website asking.
  4. The window closes and you’re in. The pass is passed to the editor in your browser. Your password never touches our website.
  5. GitHub checks you’re on the team. Signing in only works if your GitHub account has been given access to the website’s files in GitHub. Your browser remembers you, so next time it’s just one click.
!
If you see “Your GitHub account does not have access to this repo”, your account hasn’t been added to the team yet. Ask the website administrator to add you at github.com/elimbath/bath-elim-website/settings/access, then accept the email invitation GitHub sends you.

2When a visitor sends a message

This covers the contact form at the bottom of every page and the venue hire enquiry form.

Visitor→ Cloudflare→ Resend→ Church inbox
  1. The visitor fills in the form and presses Send. The message goes to our website on Cloudflare.
  2. Cloudflare checks it. It throws away empty forms, and quietly ignores spam robots using a hidden box that only robots fill in.
  3. Cloudflare passes it to Resend, using a secret key so that only our website can send email through our Resend account.
  4. Resend emails the church inbox (the address is set in Cloudflare). The subject says which form it came from and who sent it, for example “Website contact form from Jane”.
  5. You reply as normal. Pressing Reply goes straight to the visitor’s own email address.
i
Messages are not stored on the website or in GitHub; the email in the inbox is the only copy. Resend’s free plan covers up to 3,000 emails a month.

3When you update the website

For example, changing service times, adding a new page, or putting a page in the menu.

You→ GitHub→ Cloudflare→ Everyone sees it
  1. You make your changes at www.elimbath.org/admin. The preview beside the editor shows how the page will look, before anyone else can see it.
  2. You click Publish. Your changes are saved into GitHub as a new version, labelled with your name and the time.
  3. GitHub tells Cloudflare something has changed.
  4. Cloudflare rebuilds the website from the latest files in GitHub. This takes about one to two minutes.
  5. The new version goes live at www.elimbath.org. Refresh the page in your browser to see it. Until then, visitors keep seeing the previous version, so nobody ever sees a half-finished page.
i
Because GitHub keeps every past version, any mistake can be undone, even a deleted page. Ask the website administrator if you need something put back.
